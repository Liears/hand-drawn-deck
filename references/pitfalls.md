# 已知坑（按症状查）

每一条都是实际踩过的。格式：症状 → 原因 → 修法。SKILL.md 里只有一行速查，这里是可以照着排查的细节。

## 写页面

### 简表格子里的文字被撕成几列，链接浮在半空

- 症状：`.dtable` 里一段正文变成了左右几列，`<a>` 飘在格子中间，长串不换行。探针查不出来，只有截图能发现。
- 原因：`.dtable > div { display:flex; align-items:center }`。格子里每个行内元素（`<a>`、`<span>`、`<br>`、`<b>`）都被当成独立的 flex item 横排。
- 修法：每个非表头格子的内容先包一层普通 `<div>`。它成为唯一的 flex item，行内流恢复，垂直居中和行分隔线都不变。

### 读数卡下面的说明行甩出一个孤字

- 症状：430px 宽的读数卡里，"非 merge 提交 50 个 · 涉及文件 105 个"折成两行，第二行只剩一个"个"。
- 原因：数字和单位之间有空格，那就是折行点。`&nbsp;` 焊死只能保证"50 个"不被拆开，保证不了整行放得下。
- 修法：数字和单位用 `&nbsp;` 焊死；每行不超过 18 个汉字，超了主动 `<br>` 分行，别让它自己折。

### 一句话不折行，直接冲出卡片

- 症状：一句没有标点的长话横着溢出卡片，探针报 overflow。
- 原因：正文用了 `word-break: keep-all`，中文只在标点和空格处折行。一个分句比容器还宽，就没有可折的位置。
- 修法：把分句写短（三列卡里不超过 18 个字），或者加标点。不要为此去掉 `keep-all`，它防的是专有名词被腰斩。

### 两列表最后一行的行线错位

- 症状：两列表的倒数第二行，左格有行分隔线，右格没有。
- 原因：去边框的规则 `.dtable > div:nth-last-child(-n+3)` 假设了三列。
- 修法：模板用 `data-cols` 属性按列数选规则，不再写死。旧 deck 给倒数第二行的右格补行内 `border-bottom`，值同 `.dtable > div`：`1.4px solid rgba(43,36,24,.35)`。

### 改了一个数字，别的页还是旧的

- 症状：正文页更新了，账目页、索引页还是旧数字或旧状态。
- 原因：同一个数字或状态散在多页。比如提示词字节数在账目页和缺口页各有一份，"待做 / 待部署"散在下一步页和索引页。
- 修法：回写之前先 grep 全 deck 的字面量和状态词，一次改全。索引页的新 PR 行和正文页放进同一次提交，否则索引立刻过期。

### 数字改了，对比条的宽度没跟着变

- 症状：标签写的是 175ms，条还是按 180ms 画的长度。
- 原因：条宽是由数字算出来的（`width:43%` 是 180 ÷ 420 四舍五入），那一行里没有"180"，grep 搜不到。取整方式也得猜。
- 修法：模板的对比条 `.bar` 把源数字写在行内：`style="--v:175;--max:420"`，宽度由 CSS 算，和标签是同一对数。旧 deck 里手算的宽度，改数字时把它列进改动清单一起重算。

### 插页之后页码撞号，或"第 N 页"指错

- 症状：新插一页后批量把 `/ 7` 替换成 `/ 8`，最后一页从 `7 / 7` 变成了 `7 / 8`，和新页撞号；或者页内的"结论回写到第 6 页"还指向原来那一页。
- 修法：插页、删页之后，逐页把页码写成 `N / M`，不要用批量替换；再搜一遍"第 N 页"，逐个核对指向。探针的 `pagenosOk` 会拦撞号，`staleRefs` 会拦超出总页数的引用，但指向错了页又没超范围的，只能人工核对。

### 一条状态变了，别处还按旧状态说

- 症状：尾页第一条从"待拍板"改成了"已拍板"，但尾页标题还写着"还需要拍板两件事"。
- 原因：grep 状态词只搜到这一条本身，汇总它的地方（标题里的计数、账目页的处置行、索引页）没有跟着重新推导。
- 修法：状态一变，把提到它的地方都过一遍。徽标按固定语义选：`badge good` 是定了不用再跟，`badge warn` 是进行中或等结论，`badge bad` 是没开始或被卡住。

### 卡阵里一排卡的链接行高低不齐

- 原因：grid 把矮卡拉到等高，多出来的高度堆在卡片底部，看上去像底部破了个洞。
- 修法：每卡加 `display:flex; flex-direction:column`，第 ③④ 槽的容器设 `margin-top:auto; padding-top:12px`。行高差被吸收成卡片中部的留白，所有卡的链接行对齐到同一条底线。

### 截图是空页

- 原因：`.rv` 默认 `opacity:0`，等滚入才点亮。
- 修法：截之前给所有 `.slide` 加 `.on`。`shot-deck.mjs` 已经内置，不要另写截图脚本。

## 字体

### 打开后根本不是手写体：中文是黑体，数字是普通无衬线体

- 症状：整份页面都是系统字体。用模板起手的 deck 会在页顶出一条红底提示"字体未加载"。
- 原因：`fonts/fonts.css` 没加载上。最常见的是在 skill 目录里直接打开 `assets/template.html`——字体文件不进仓库，那里没有 `fonts/`；或者刚拷完模板还没跑子集脚本，`fonts.css` 还不存在。
- 修法：把模板拷到 deck 目录，跑一次 `refresh_cjk_subset.py` 再打开。只想先看效果，看 `assets/template-preview.png`。发给别人的时候整个目录一起发，`index.html` 离开 `fonts/` 就会回落成系统字体。
- 排查自己写的提示逻辑时注意两点：`document.fonts` 里的字体声明要等样式表应用之后才登记进来，`load` 事件那一刻可能还是空的；而且它是类 Set 的集合，没有 `length`，用 `Array.prototype.slice.call` 取永远是空数组。

### 中文里夹着印刷体的字

- 原因：子集里没有这个字，浏览器回落到了系统字体。要么改了文案没重跑子集脚本，要么这个字符不在收集范围内。
- 修法：重跑 `refresh_cjk_subset.py`。脚本自带覆盖自检，会点名缺的字；探针的 `missing` 会进一步指出缺的字在哪个元素里。

### λ、μ、²、⁷ 这类字符显示成印刷体

- 原因：早期脚本只收集 CJK 区的字符，希腊字母、上标、微符号都不收，于是静默回落，自检也看不到它们。Xiaolai 全量字体其实有这些字形（共 44871 个）。
- 修法：现在的脚本收集全部非 ASCII 字符，重跑即可。

### 源字体本身没有的字形

- 症状：自检打印 `[verify] ✗ Xiaolai 缺 N 个字形`。
- 原因：Xiaolai 没有 emoji 这类字符，浏览器必然回落。
- 修法：逐个决定——换写法（如 ①→1.）、换字体，或人工接受回落（把字符写进 `<meta name="fallback-ok" content="…">`）。不允许静默带病交付。

### 下载的字体只有几百字节，或者只有半截

- 原因：经 gh-proxy 这类代理下载，小于 1KB 的大概率是错误页。22MB 的 Xiaolai 还容易传到一半超时——实测 180 秒超时，只拿到 9.9MB。
- 修法：下载后用 `ls -la` 和 `file` 核对（Xiaolai 约 22MB，JetBrains Mono 约 270KB）。断了用 `curl -C -` 从断点续传。

### Xiaolai 下载 404

- google/fonts 仓库里 Xiaolai 的路径是 404；jsdelivr 对该仓库的 raw 地址返回的是错误页。用 SKILL.md 字体管线里给的地址。

### fontTools.subset 报 invalid literal for int()

- 原因：`--unicodes` 接受的是十六进制码点列表，不是字面字符。

### 改了字体或 CSS 之后，浏览器还在用旧的

- 原因：URL 没变，缓存没有失效。
- 修法：不要手改，两处 `?v=` 都由脚本同步，含义不同：`index.html` 里 `<link>` 的 `?v=` 是 fonts.css 自身的内容哈希，fonts.css 里每个字体的 `?v=` 是各自字体文件的内容哈希。所以两处的值本来就不相等，这是设计如此。

### 改了一个字，git 却显示整份 index.html 全量变更

- 原因：Windows 上 Python 的文本读写默认做换行转换，LF 的文件写回去就变成了 CRLF。
- 修法：新版子集脚本用不转换换行的方式读写，LF 的文件跑完还是 LF。旧 deck 如果已经被转成 CRLF，先 `git diff --stat` 确认只有换行变化，再决定要不要还原。

### skill 里和 deck 里各有一份子集脚本

- 原因：早期做法是把脚本拷进 deck 的 `scripts/`，skill 更新之后两份就不一致了，没人说得清以哪份为准。
- 修法：直接跑 skill 里的那一份，把 deck 目录当参数传进去：`python3 "$SKILL_DIR/scripts/refresh_cjk_subset.py" "$DECK"`。

## 探针与浏览器

### node 报找不到 playwright

- 原因：脚本放在 skill 目录或临时目录时，依赖按脚本所在目录解析，找不到。
- 修法：到装了 playwright 的项目根目录里运行。脚本内部已经按当前目录解析：`createRequire(path.join(process.cwd(), 'noop.js'))`。

### 浏览器启动失败：Executable doesn't exist

- 原因：playwright 想要的 build 不在缓存里。常见于依赖升级之后——比如仓库依赖要 chromium_headless_shell-1217，缓存里只有别的版本。
- 修法：`npx playwright install chromium`；或者把 `CHROME_EXE` 指向本机已有的 Chrome / Edge。默认浏览器不存在时，脚本会自动借用缓存目录里现成的其它 chromium 版本，并打印用的是哪一个。缓存目录按平台不同：Linux 是 `~/.cache/ms-playwright`，macOS 是 `~/Library/Caches/ms-playwright`，Windows 是 `%LOCALAPPDATA%\ms-playwright`。

### 自己写缺字检测时：document.fonts.check() 是恒真的

- 现象：`document.fonts.check('20px Xiaolai', '龘')` 对子集里没有的字也返回 `true`。
- 原因：它只回答"匹配到的字体面是否已加载"，不看 cmap。只要 Xiaolai 加载成功，对任何字符都返回 true。`document.fonts.load()` 同理。
- 修法：用探针里的办法——同一字符分别用"该字体"和"一个不存在的字体"在画布上渲染，像素完全一致就说明回落了。两个细节缺一不可：
  - 用 `alphabetic` 基线。`textBaseline:'top'` 会跟着主字体的 em 方框移动，同一个回落字形也能差出几千个像素。
  - 画布开 `willReadFrequently`，走 CPU 渲染，结果稳定。

### 自己写溢出检测时：带内边距的元素有盲区

- 现象：代码窗里一行 73 列，内容区只放得下 72 列，`scrollWidth` 却没有变大。
- 原因：文字伸进右侧内边距时，浏览器的可滚动溢出区本来就包含这段内边距，所以 `scrollWidth > clientWidth` 不成立。
- 修法：探针对"子元素都是行内级、且有左右内边距"的元素，改用 Range 量文字的真实左右边界，再和内容区比。没有内边距的元素（`<p>` 这类）仍然用 `scrollWidth`，结果精确。

### 没有代码窗的 deck，探针报字体不全

- 症状：`[FAIL] fonts=["Xiaolai","Excalifont"]`，少了 JetBrains Mono，其余全过。
- 原因：浏览器只在有文字用到某套字体时才加载它。deck 里没有等宽文本，JetBrains Mono 就不会加载，而旧探针只看"已经加载了哪些"。
- 修法：探针现在先把 `@font-face` 声明的字体各加载一遍再判断。不要为了让探针过，把页码之类硬改成等宽字体。

### 页高和基线对不上

- 现象：探针输出的 `heights` 比在 1920 宽截图里量的矮一截；模板示例页全部低于"正常页 810–1150px"。
- 原因：探针的视口宽是 1680，`fit()` 把页面缩到 0.875×，`getBoundingClientRect` 量出来的是缩放后的值。单页高度基线就是按这个口径标定的，直接对照即可；页比下限矮不是问题，超过 ~1400px 才需要拆页。
- 修法：要未缩放的设计稿像素，看 `[INFO]` 行的 `designHeights`。

### 截图互相覆盖，旧图冒充现状

- 症状：deck 从 8 页改成 6 页之后，目录里还留着第 7、8 页的旧图；两份 deck 的截图混在一个目录里。
- 原因：早期所有截图都写到同一个固定目录，文件名只有页码。
- 修法：`shot-deck.mjs` 现在默认写到 `<系统临时目录>/deck-shots/<deck 名>/<时间戳>/`，改前改后各有一份。改之前先截一套，改完对照着看。

### 截图看不到

- 执行环境可能把截图转存成外链，而不是内联图片。字符级验收靠探针；布局级验收把截图落到本地文件后自己读。

## 设计取舍

### 手机宽度下整份 deck 缩到 0.22×

- 现象：420px 宽的窗口里，`fit()` 按 1920 的设计宽把页面缩到 0.22×，20px 的字只剩 4px 多。
- 原因：`fit()` 只设了 1.3× 的上限，没有下限。这是"设计宽 1920、按视口宽缩放"这条设计决定的固有结果。
- 现状：没有改。交付时如实告诉用户：这份 deck 是给电脑窗口读的，手机上需要放大。

## 平台

### Windows：Python 脚本在最后一行崩 UnicodeEncodeError

- 原因：stdout 接的是管道时，Windows 按系统编码输出，中文系统是 GBK，`✓` `✗` 编不了。生成物其实已经落盘，但退出码是 1，自检结论也丢了。
- 修法：脚本开头已经把 stdout 和 stderr 重设成 UTF-8。自己写小工具时照做：`sys.stdout.reconfigure(encoding='utf-8')`。

### Windows：敲 python3 没反应，或者弹出应用商店

- 原因：`python3` 可能只是微软商店的占位符。
- 修法：用 `python` 或 `py`。

### 中国大陆装 Python 包

- vitest、子集等任何 Python 工具装包，用阿里云 pip 源：`-i https://mirrors.aliyun.com/pypi/simple/`。

### docker run --platform linux/amd64

- aarch64 机器上需要先注册 qemu binfmt（做过，约 29 倍减速）。与 deck 无关，但常被一起问到。
